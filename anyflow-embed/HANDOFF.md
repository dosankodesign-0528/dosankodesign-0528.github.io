## 4. アーキテクチャ

### 4.1 奥行き（前後）の仕組み

軌道は **奥レイヤー SVG → 惑星 canvas → 手前レイヤー SVG** の3層。

- 奥 SVG: 楕円の全周＋「奥側を通行中のドット」
- 手前 SVG: 楕円の手前半分（clipPath で下半分を切り出し）＋「手前側のドット」
- ドットはパラメトリック角度の `sin(t) > 0` が手前。`renderFrame()` で毎フレーム表示レイヤーを切替
- これで奥を通る線・ドットは惑星の裏に隠れる（カンプの重なりと一致）

軌道のジオメトリはパネル設定を反映して毎フレーム `orbitGeom()` → `updateOrbitSvg()` で
SVG属性（cx/cy/rx/ry/transform、クリップ矩形、グラデ座標）を再計算する。
ドット位置も同じジオメトリから計算するので、軌道をいじってもズレない。

### 4.2 惑星（WebGL）

- 素の WebGL（ライブラリなし）。フルスクリーントライアングル＋フラグメントシェーダー
- **惑星ごとに別プログラムをコンパイル**（`DESIGNS` の各エントリ）
- B/C/D: カンプ画像をテクスチャとして球面に貼る方式
  - `uv = (0.5 + d.x*0.47, 0.5 - d.y*0.47)`（d = 回転後の法線）
  - 無回転時はカンプがピクセル一致で表示される。裏側はカンプに無いので鏡映で生成
  - デザイン別の `finish`（GLSL片）で粒・ハイライト・リムを仕上げ（B: 乗算粗粒 / C: 境界中粒 / D: 高密度微粒）
- E（ハーフトーンブルー）: **完全生成**（`fragment` に独自シェーダー全体を持つ。テクスチャ不使用＝継ぎ目なし）
  - 明るさの場 `lum` → 6段階量子化 ＋ ベイヤーディザ（2px セル）でピクセル調
  - カラーランプ: マゼンタ⇄紫⇄深青⇄青⇄シアン⇄白（`ramp()`、負の値で紫帯）
  - ディザ演出（`uDither`）: ①固定 ②うつろい ③流れ ④さざ波 — **色の場を波で動かして**境目のピクセルがパラパラめくれる方式（しきい値だけ動かす方式はNGだった経緯あり）
- 回転: 軌道の傾きとはずらした2軸合成（`ax1`, `ax2`、`uAngle`/`uAngle2`）。上下の位置揺れはなし
- ライト（`uLight`）: ①なし ②右上光源。②は右上からの平行光＋影は**青みに沈める**（グレー化させない）。ハイライトは白飛びさせない
- WebGL 不可時: canvas 背景にカンプ PNG を表示するフォールバック

### 4.3 アニメーションクロック

- `elapsed`（秒）が唯一の時間源。`requestAnimationFrame` で加算、`params.running=false` で停止
- すべての動き（ドット周回・自転・ディザ・ゆらぎ・軌道ゆれ）が `elapsed` から計算される＝一時停止で全部止まる
- ドット角度: `patternDeg()` = 緩急ゆらぎ（サイン波の速度変調 `warpTime`）＋遅延・ランプ・個別スピード
- **デバッグ用フック** `window.__anim`: `setElapsed(t)` / `step(dt)` / `setSway(n)` / `setDesign(k)` / `setDither(n)` / `setLight(n)` / `getState()`
  - ⚠️ Claude の Browser プレビューペインでは rAF が発火しない。検証は `setElapsed()` で時間を進めてスクショ比較する

### 4.4 パラメーター

- `DEFAULTS` がすべての初期値。ユーザー操作は `localStorage`（キー `anyflow-embed-anim-v4`）に保存
- `load()` はデフォルトと deep-merge ＋ 削除済み選択肢のバリデーション
- 構造: `sway / design / dither / light / duration / globalSpeed / direction / ramp / pulse{amp,period} / sphere{duration,tumble,noise} / planet{dx,dy,scale} / orbits{outer,inner}{scale,angle,dx,dy,wobbleAmp,wobblePeriod,wobblePhase} / marquee{duration,direction} / dots[6]{speed,delay,offset,pulsePhase}`
- **軌道のゆれ位相は outer=0 / inner=180 がデフォルト** → 両方のゆれ幅を上げるだけで2本がクロスする

1. **🎛 パターン切替スイッチャー**（初期位置 左下）

   - アコーディオン式セクション: ゆらぎ（固定/シーソー/クロス）・惑星（B/C/D/E）・ライト（なし/右上光源）・ディザ（E選択時のみ表示: 固定/うつろい/流れ/さざ波）
   - 閉じたセクションは右側に現在の選択名を表示
   - **「📋 いまの設定をコピー」ボタン**: 現在の `params` を JSON でクリップボードへ。
     これを Claude に貼れば `DEFAULTS` に焼き込んで「全訪問者のデフォルト」にできる（デフォルト化ワークフロー）

## 7. スクロールセクション（KV以降・2026-08-13 実装）

絵コンテ（STORYBOARD-NOTES.md）とデザイン本体（Figma node `14693-28238`, TOP 1440×7425）を元に
KVより下の全セクションを実装した。ライブラリなし、素の sticky + スクロール進捗計算。

### 構成と仕組み

- **ピン留めセクション** (`.pin` > `.pin-vp`(sticky 100vh) > `.pin-stage`(1440×921を`--sp`でスケール))
  - `#vision` … Our Vision 文字出現→左スライド→ミニ楕円→文字退場→楕円がPlatform図へ移動拡大→
    ドット周回して停止→役割ラベル→「連携が生む、2つの価値」→Point 01/02
  - `#dev` … ダーク。見出しブラー出現→上下分割→間からモック拡大→ブラー切替→2巡目→
    モック右ドック→CLI/API/SDK切替（**ここは絵コンテで「Claude補完」指定 → 複数案あり**）
  - `#cases` … 導入事例。**スティッキースタック**（カンプ `14767:16333` 準拠）
- **通常フロー** `#results` … 画面に入ったらグラデ画像鮮明化＋カウンター（ランダム→確定、
  200+/500+/99.9%。1weekはカウントなし＝絵コンテ指定）
- 進捗計算は `pinP()`、フェーズ分割は `VIS_P` / `DEV_P` / `CASE_IN` 定数（0〜1の区間）
- すべて `renderFrame()` → `updateSections()` で毎フレーム適用（一時停止はカウンターにも効く）

### スクロールのリプレイはしない（2026-08-14）

- 各セクションの自動再生の開始時刻（`visAutoT0` / `resT0` / `devHoldT0` など）は
  **一度動き出したら null に戻さない**。スクロールで戻っても再生し直さず、終わった状態のまま
- リロード時は必ずKVの先頭から。`history.scrollRestoration = 'manual'` ＋ `scrollTo(0,0)`
  （ブラウザ既定の位置復元が効くと、途中から復元されて自動再生が中途半端に始まる）
- 頭から見直したい時は 調整パネルの「↺ 最初から」か `__anim.replay()`。
  どちらも `resetSectionClocks()` を呼ぶ。**新しい時間駆動アニメを足したら、この関数にも追加すること**

### ビジョンの進み方＝【出だしだけ自動、あとは全部スクロール】（2026-08-14 ヒデさん選択）

| | 何で進むか |
|---|---|
| 「Our Vison」＋1行目が出るまで（`VIS_AUTO_HEAD` = 2.05秒） | **時間**（到着した瞬間に反応が返るように） |
| 2行目 → 上下に分かれる → 軌道が出る → 左下へ → 2つの価値 | **ピン中のスクロールだけ**（手を止めれば絵も止まる） |

```
A = min(VIS_AUTO_HEAD, 経過秒) + clamp01(p / 0.88) × (VIS_TOTAL − VIS_AUTO_HEAD)
visT = max(前回値, A)     ← 巻き戻さない
```

⚠️ **経緯**: もともと全部が時間駆動 → 空スクロールの指摘で「時間とスクロールの速い方」に
→ それでも「時間で勝手に進む」と指摘されて現在の形へ。**`max()` に経過秒を混ぜ戻さないこと**。
`line2Gap` を 1.15 にしてあるのは、1行目が出きった直後にスクロール側へバトンを渡すため。

### 見出し「つなぐことが、強みになる時代へ。」の出し方（2026-08-14 作り替え）

**中央寄せ → その場で上下に分かれ、間から軌道グラフィックが出てくる**形。
（絵コンテ4コマ: ①中央にOur Vison＋1行目 ②2行そろう ③上下に分かれて間にミニ軌道
 ④全部ブラーで消えて軌道だけ残る）

- `.vis-label` / `.vis-line` は `left:0; right:0; text-align:center` の中央寄せ
- `splitGap`(分かれ始めるまで) / `splitDur`(分かれる時間) / `splitAmt`(開く量・片側92px)
- 「Our Vison」は分割と入れ替わりで消える（`(1 - spK)`）
- ミニ軌道は**2行のちょうど間・画面中央**。
  ⚠️ `.pf-wrap` は `top:127px` なので、楕円中心のステージ座標は `127 + 333.5 + ty`。
  ここを間違えると軌道が2行目に重なる（実際に踏んだ）
- 以降（軌道が左下へ移動＋実寸 → 2つの価値）は従来どおり

🗑 **廃止**: 中央→左へのスライドと、その4案（`VISION_SLIDES` / `SLIDE_EZ` /
`slideX1,2` / `slideStagger` / `charStagger` / `measureVisCenter`）。**復活させないこと**。

### （旧）見出しの左スライド 5案 ※廃止済み

`VISION_SLIDES` / `SLIDE_EZ` で定義。調整パネルの「📖 ビジョン › 左へのスライド（動きの種類）」で切替。

### 導入事例のスティッキースタック（2026-08-14 作り直し）

カードは**カンプのように縦に gap 40px 空けて並んだ状態**で出てきて、
スクロールするとリストごと上へ流れ、上端に着いたものから順に貼り付いて重なる
（2026-08-14: 画面外から1枚ずつ飛び込む形をやめた）。

終着点は **3枚とも上端 172（＝「導入事例」の上っ面）にぴったり重なった状態**
（2026-08-14 ヒデさん指示: 「完全に全部3つ重なる／位置としては同じ位置で終わってほしい」）。
奥へ送られるたびに 0.1 ずつ縮小するので、奥のカードは手前のカードの内側に隠れる。

| | 上端 | 幅 | 縮小率 |
|---|---|---|---|
| 1枚目 SmartHR（最奥） | 172 | 704 | 0.80 |
| 2枚目 deex | 172 | 792 | 0.90 |
| 3枚目 SALES GO（最前） | 172 | 880 | 1.00 |

3枚とも**左右中央そろえ**（前面カードの右端が余白120px）。
※カンプ `14767:16333` は 172 / 251.8 / 366.1 と段差のある重なりだった。
段差を戻したい時は調整パネルの「重なりのズレ」を上げる（0 = 完全に重なる）。

動きは `arr`（何枚目まで積み上がったか 0→2）1本で決まる。
1枚目はその場でブラー出現、2枚目以降は画面下から上がってきて所定の位置に貼り付き、
新しいカードが着地するたびに前のカードが縮んで奥へ下がる。

| 名前 | キー | 既定 | 意味 |
|---|---|---|---|
| 出現ブラー | `cases.inBlur` | 20px | カードが出てくる間のぼけ量 |
| 奥行きの強さ | `cases.depth` | 100% | 1段につき縮小10%（100%で 0.8/0.9/1.0） |
| カードの間隔 | `cases.gap` | **40px** | 並んでいる時のカード同士の縦の間隔 |

**やめたこと**（2026-08-13〜14 に入れていたが、カンプに無い動きだった）:
3枚を縮小して縦に並べる状態 / 重なる時に実寸へズームする動き / 出現の自動再生（時間駆動）。
これらが「デフォルトの見た目もスクロール中の挙動もおかしい」原因だった。

⚠️ 位置とサイズは**画面上の見え方で補間してからリストの縮小率で割り戻している**。
素直にリスト座標で補間すると、拡大中に3枚目が一度画面下へはみ出してから戻る動きになる。

### 実装上の判断・注意

- **開発者モックはHTML/CSS製**（`.dm-panel`、コード行は `DM_ROWS` 定数から生成）。
  Figmaの画像書き出しはガラス半透明が白く焼き付くため画像は不採用（assets/dev-mock.png は参考用に残置）
- Platform図の楕円は Figma SVG書き出しの実数値（同一楕円 rx473.8/ry158.9 を -23.33° と -5.37° の2枚重ね、
  グラデはKVと同系）。ドット停止位置はカンプ座標から楕円式で逆算した角度（`PF_DOTS`）
- **線の太さはカンプの `stroke-width: 3`**（2026-08-14 に4→3へ修正）
- **Platform図の文字はカンプが字間を広く取っている**。カンプのテキスト幅から逆算して

## 7.5 スマホ対応（2026-08-14 / まずは一次対応）

**PCの 1440×921 をそのまま縮めない**。390px幅で縮めると本文が4pxになって読めないため、
**設計フレームごと 390×780 に差し替える**方式にしてある。

- `fit()` で `w <= MOBILE_MAX(780)` なら `DW=390 / DH=780`、`<html>` に `.mb` が付く
- 高さは CSS 変数 `--dh` で全ステージに配る（`.flow-stage` / `.pin-stage` / `#results .pin-stage`）
- **CSS は `@media (max-width: 780px)` の1ブロックに集約**。ここに書く数値は 390px幅の実寸そのもの
- JSでジオメトリを計算している所はスマホ分岐がある:
  | 対象 | スマホでの扱い |
  |---|---|
  | KVの軌道グループ | JSの transform に `scale(0.40)`。CSSで原点を左上・左寄せに |
  | ビジョンの軌道図 | `kFill` の基準幅を 1440 → **900** に（画面幅いっぱいに見せる） |
  | 図の中の文字 | 図が縮むぶん **CSSで大きめのfont-size**を置いて実効サイズを稼ぐ |
  | 開発者体験のモック | `mockK()=0.40` で縮小。**右へドックせず中央のまま**（`mockCenterX()` が 0 を返す） |
  | 導入事例のカード | **写真が上・文章が下の縦組み**に変更。`caseH()=372 / caseTop()=118` |
- 見出しの `top` は HTML の inline style なので、`#devH1 / #devH2` は `!important` で上書きしている
- ⚠️ 780px以下は全部このスマホ用レイアウト。タブレット横（1024px前後）はPCレイアウトが
  55〜70%に縮んだ状態になる。気になるなら中間ブレークポイントを足す


## 7.6 参考36サイトの実測から入れた「動きの共通ルール」（2026-08-14）

Eagle『プロジェクト > Anyflow > Rebranding > 参考サイト』36サイトを全件ブラウザ実測して反映した。
計測メモの要点:

- **Lenis(慣性スクロール)採用率 21/36 = 58%**。ただし**日本のサイト5件は全部Lenisなし**で、
  CSSトランジションの秒数とカーブだけで質感を作っていた
- **固定(sticky)が2画面を超えるサイトは1つも無かった**（最長の sakazuki.io は全長30画面だが
  固定は1〜2画面ぶんずつ）
- いちばん多かったカーブは **`cubic-bezier(.22,1,.36,1)`（easeOutQuint）**

### 動きのトークン（CSSとJSで同じ値を持つ）

| 用途 | CSS | JS | カーブ |
|---|---|---|---|
| 小さい反応(ホバー等) | `--t-fast: .25s` | `T_FAST` | `--e-fast` = `cubic-bezier(.4,0,.2,1)` |
| 出現 | `--t-in: .8s` | `T_IN` | `--e-out` = `cubic-bezier(.22,1,.36,1)` |
| 大きい移動 | `--t-big: 1.3s` | `T_BIG` | 同上 / JSは `easeSlick` |

**`easeOutQ`（JS）と `cubic-bezier(.22,1,.36,1)`（CSS）は同じカーブ**。新しく動きを足す時は
この3段階のどれかに必ず寄せること（以前は 0.8/0.9/1.4/1.5/1.9秒がバラバラに散っていた）。

### 慣性スクロール (Lenis)

- `assets/lenis.min.js` に**自前ホスト**（CDN依存にしない）。`frame()` の先頭で `lenis.raf(ts)`
- `duration: 1.1` / easing は easeOutQuint（トークンと同じカーブ）
- **スマホは `syncTouch: false`** で端末標準の慣性に任せる
- OSで「視差効果を減らす」にしている人には掛けない
- ⚠️ **`html { scroll-behavior: smooth }` は入れないこと**（Lenisと喧嘩する）
- ヘッダーのアンカーリンクは `lenis.scrollTo()` 経由に差し替え済み

### 見出しの1文字ずつ出し

`vision.charLag`（既定 0.5）。0 にすると従来の行まるごと出しに戻る。
⚠️ 案C（文字ごと横流し）と**同じ `style.transform` を取り合う**ので、
縦の出現と横のスライドは**1回の代入にまとめて**当てている。別々に書くと後勝ちで消える。


### 🚨 空スクロールの見つけ方と潰し方（2026-08-14 に全セクションで実施）

「所定の位置に来たのに何度もスクロールしないと進まない」は、原因が必ずこの2つのどちらか。

1. **セクションが時間駆動だけで動いている** → ピン中にスクロールしても進捗が1ミリも動かない。
   ビジョンがこれだった（1.6画面ぶん完全な無反応）。実績も同じ穴があった。
   → **`max(前回値, 経過時間, スクロール由来の時間)`** にして「速い方で進む」形にする。
     止まっていても勝手に再生され、スクロールした分はちゃんと進み、巻き戻りもしない
2. **乗り換え区間(必ず1画面)が空っぽ** → `preP(sec)` で助走ぶんを進捗の頭に繰り込む。
   開発者体験は `PRE = 0.12` として、1つめの訴求文が助走のうちに出るようにした

**確認方法**（実測したコード。困ったらこれを回す）:
```
const yPin=(s,p)=>s.offsetTop+p*(s.offsetHeight-innerHeight);
const yPre=(s,q)=>s.offsetTop-innerHeight+q*innerHeight;
// 「前セクションが出そろう位置」と「次セクションが動き出す位置」の差を画面数で見る
```
2026-08-14 時点の実測: ビジョン完了→実績開始 **0.27画面** / 実績完了→開発開始 **0.19画面** /
白くなり切る→導入事例の文字 **0.06画面**。**0.3画面を超えたら要調整**。

### 調整パネル（2026-08-14 に作り直し）

- **外寸を固定**（既定 360×520px）して、中身だけ `.panel-body` でスクロールさせる。
  ⚠️ 高さを内容で決めると、アコーディオンを開くたびにパネルが伸び縮みして
  **触っている場所がズレる**（レイアウトシフト）。実際に苦情が出た
- `.panel-body { overscroll-behavior: contain }` でページへスクロールが伝播しないように
- ⚠️ **Lenis に `prevent` を渡さないと、パネル内のホイールをページに全部持っていかれる**
  → `prevent: node => !!node.closest('.tools')`
- ヘッダーを掴んでドラッグで移動（`.tools` を left/top 指定に切り替える）。
  右下つまみでリサイズ（`resize: both`）。ドラッグした時は開閉トグルを発火させない
