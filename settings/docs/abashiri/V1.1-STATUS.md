### 動画

`public/video/ryuhyo.mp4` は **1280×574 / 157秒 / 23.5MB / 約1.3 Mbps**。
982px の高さに引き伸ばすとぼやける。元素材は `_source/`（git 管理外）にある。

⚠️ **GitHub は 100MB 超のファイルを受け付けない**（ローカルから push しても同じ）。
差し替える時は、下の目安まで圧縮してから入れること。

| 目安 | 幅 | 尺 | ビットレート | 出来上がり |
|---|---|---|---|---|
| おすすめ | 1600px | 60〜90秒 | 3〜4 Mbps | 30〜45MB |
| 上限 | — | — | — | **100MB 未満（必須）** |

```sh
# 60秒だけ切り出して、幅1600・3.5Mbps に圧縮する例
ffmpeg -i _source/流氷クルーズ.mov -ss 0 -t 60 \
  -vf "scale=1600:-2" -c:v libx264 -b:v 3500k -preset slow \
  -pix_fmt yuv420p -movflags +faststart -an \
  abashiri/v1/public/video/ryuhyo.mp4
```

## 実装の地雷（踏んだやつ）

1. **ステージ幅に 1512 を直書きしない。** ステージは横長画面だと 1512px より広がる。
   中央ぞろえや遷移の終点は必ず器の実寸（`root.offsetWidth`）から出す。
   カルーセルが中央からずれた／窓枠が左上に飛んだ、はどちらもこれが原因
2. **位置と大きさに別々のイージングを当てない。** ひとつの進行度から矩形の中心と大きさを
   両方出す。別々にすると小さいまま位置だけ終点へ走って破綻する
3. **`pkill -f "next start"` は自分自身にマッチしてシェルごと落ちる。** 使わない
4. **framer-motion が opacity を握っている要素に、style で opacity を書いても効かない。**
   フェードは外側のラッパーに持たせる
5. **ヘッドレス Chromium は H.264 をデコードできない。** 動画の再生確認はこの環境では不可能。
   検証は要素の同一性・座標・computed style で取る
