## 0. このドキュメントの立ち位置

- **値の唯一の出どころ = `anyflow/v3/index.html` の `<style>` 冒頭にある `:root{}` トークン群**
  （`/*DS-TOKENS-START*/` 〜 `/*DS-TOKENS-END*/` で囲ってある）。
- **ドキュメントとコードがズレたら、コードが正。** ここは早見表。
- 本番コンポーネントは HEX・rgba・px を直書きせず、`var(--トークン名)` で参照する。
  直書きしたくなったら、それは「**名前が足りない**」サイン。ここに1行足してから使う。

### 何を触って、何を触っていないか（超重要）

| 対象 | 扱い |
|---|---|
| **本番サイトのCSS**（ヘッダー〜フッター、開発モックの見た目） | ✅ トークン化した |
| **KV（キービジュアル）の iframe**（`kv/` 配下）・**惑星/軌道の canvas**・パターン生成 | ❌ 生成アートなので据え置き（見た目維持） |
| **調整パネル（画面右上から出る開発UI）** | ❌ 開発用チラシなので据え置き |

> 整備は「見た目を変える作業」ではなく「**値に名前を付けて出どころを1か所に集める**作業」。
> **既定は Mid（2026-08-29 ヒデさん採用・`<html data-ds="mid">`）**。見た目は現行とほぼ同じ（差は下の表の2件のみ）。
> `?ds=low` を付ければ現行 V3 と **完全に一致**する（下の検証を参照）。

### 命名の考え方

| 決め方 | 対象 | 例 |
|---|---|---|
| **カテゴリ + 値** | 大きさで決まるもの（角丸・余白・ブラー） | `--radius-lg` `--space-24` `--blur-panel` |
| **カテゴリ + 役割** | 意味で決まるもの（色・影・イージング） | `--brand-cyan` `--ink` `--shadow-mock-panel` |

- **色は見た目で名付けない。** `--blue` ではなく `--brand-cyan`（役割）。色を変えても名前が生き残る。

## 1. 整備レベル（Low / Mid / High）と切り替え方

同じデザインを **3段階の整備レベル**で持っている。`<html>` の `data-ds` 属性で切り替わる。

| レベル | 何をした | 見た目 | 色トークン(実質の異なる値) |
|---|---|---|---|
| **Low**（最小整備・`?ds=low`） | 今の値を全部そのまま。名前を付けただけ | **現行と完全に一致** | 22 |
| **Mid**（バランス・`?ds=mid`） | 見分けのつかない重複だけ統合 | ほぼ不変 | 20 |
| **High**（★採用・既定） | 色数を最小化（サーフェス9→4色ほか）・角丸/余白も圧縮 | 小さな変化あり | 14 |

> **本番の既定は High**（`<html data-ds="high">`・2026-08-29 採用）。色数を一番絞った版。
> 現行と完全一致で見たい時は `?ds=low`、中間は `?ds=mid`。

### 切り替え方

- **URL で**: `index.html?ds=low` / `?ds=mid` / `?ds=high`（`<head>` の小さなスクリプトが読む）
- **比較ビューア**: `anyflow/v3/mock/design-system/`（タブで Low/Mid/High を切替え、実物を iframe 表示）
  - 本番URL例（デプロイ後）: `https://anyflow-embed-v3.vercel.app/mock/design-system/`
- **既定の固定**: `<html data-ds="high">` を直書き済み（＝本番は High）。`mid`/`low` に書き換えれば既定を変えられる。
  URL の `?ds=` は常にこの既定より優先される。

### レベルごとの差分（実測で確認済み）

**Low → Mid**（目で見た変化はほぼゼロ）
| 変えたトークン | 前 → 後 | 理由 |
|---|---|---|
| `--code-string` | `#9BE8A4` → `#7CE7A6` | コードモックの緑2色が近すぎるので1つに |
| `--surface-footer-bottom` | `#434343` → `#454545` | フッター暗色と開発暗色が差2/256＝不可視。統合 |

**Mid → High**（小さな見た目差が出る）
| 変えたトークン / 箇所 | 前 → 後 | 見え方 |
|---|---|---|
| **サーフェス全体** | **9色 → 4色** | 地色#E7E7E7 / 黒#090909 / 暗#161616 / 中暗#454545 に集約 |
| `--surface-terminal` | `#080A0E` → `#090909` | CLI端末の黒をCTA黒に統合（不可視） |
| `--surface-mock-1/2/3` | → `#161616` | 開発モック地を暗セクション色に統合（ガラス重ねで面は保つ） |
| `--line-grid` | `#ACACAC` → `#D1D5DC` | 導入事例グリッドの罫線が少し明るくなる |
| `--ink-label` | `#333333` → `#101828` | 実績ラベルのグレーが本文の濃紺へ寄る |
| `--radius-md` / `--radius-lg` | `14→8` / `24→16` | チャット吹き出し・モックパネルの角が控えめに |
| 余白 `.res-main` / `.res-col` / `.cg-body` | `34→32` / `59→60` / `27→24` | はみ出し余白が8pxグリッドに揃う |

> **本番は High を採用**（色数最小）。現行と完全一致で見たい時は `?ds=low`、中間の Mid は `?ds=mid`。

## 2. カラー

### ブランド
| トークン | 値 | 使いどころ |
|---|---|---|
| `--brand-cyan` | `#0EBBFF` | 主役の水色。キャレット/リンク/アイコン/Strengthラベル |
| `--brand-pink` | `#FF5D97` | 差し色のピンク。タグ■/AIアバター/コードの予約語 |
| `--brand-blue-deep` | `#0E4497` | 濃紺。グラデの相方/「AI」タグ |

### インク（文字・マーク）
| トークン | 値 | 使いどころ |
|---|---|---|
| `--ink` | `#101828` | 本文の基本色（濃紺グレー・カンプ指定） |
| `--ink-strong` | `#000` | 純黒。見出し/罫/カンプで黒指定の所 |
| `--ink-label` | `#333333` | ラベルのグレー（実績の見出し等）※Highで`--ink`へ寄せる |
| `--ink-on-dark` | `#fff` | 暗い面の上の白文字 |

### サーフェス（背景）
値は Low の実測。**採用中の High では 4色に集約**（右端に High の寄せ先）。

| トークン | 値(Low) | 使いどころ | High |
|---|---|---|---|
| `--surface` | `#E7E7E7` | ページ全体の地色（V3の基調） | そのまま |
| `--surface-dark-top` | `#161616` | 暗いセクションの上端（開発者体験/フッターのグラデ開始） | そのまま（暗の基準色） |
| `--surface-dark-bottom` | `#454545` | 開発者体験セクションのグラデ下端 | そのまま |
| `--surface-footer-bottom` | `#434343` | フッターのグラデ下端（※上とほぼ同値） | → `#454545` |
| `--surface-cta` | `#090909` | CTAボタンのほぼ黒 | そのまま（黒の基準色） |
| `--surface-terminal` | `#080A0E` | CLI端末の背景 | → `#090909` |
| `--surface-mock-1/2/3` | `#2B2B2B`/`#232323`/`#1B1B1B` | 開発モックパネルの暗いグラデ3点 | → `#161616`（ガラス重ねで面は保つ） |

→ High のサーフェスは **`#E7E7E7`（地）/ `#090909`（黒）/ `#161616`（暗）/ `#454545`（中暗）の4色**。

### 線・コード・ガラス
| トークン | 値 | 使いどころ |
|---|---|---|
| `--line` | `#D1D5DC` | 区切りの細線（実績の罫/縦線） |
| `--line-grid` | `#ACACAC` | 導入事例グリッドの罫線 |
| `--code-green` | `#7CE7A6` | コードの「成功/OK」 |
| `--code-string` | `#9BE8A4` | コードの文字列（Mid/Highで`--code-green`へ） |
| `--glass-10` | `rgba(255,255,255,.10)` | 暗い面の上の白（面/境界。いちばん多い） |
| `--glass-06` | `rgba(255,255,255,.06)` | 薄い面/境界 |

> ⚠️ **KV・惑星の生成アートの色は含めない**（`#00ABEB` 軌道線・WebGL/canvasの色など）。あれは別世界。

## 3. テキスト（サイズ・ウェイト）

font-size は現状コンポーネント側の px 指定のまま（ここは早見表）。書体は `--font-en` / `--font-jp`。

**ウェイトの段**: 100(Thin) / 200(ExtraLight) / 300(Light・本文の基本) / 400(Regular) / 500 / 600
**主なサイズ**: 12・14（本文/ラベル/CTA）・16（ナビ/リード）・20（Strength/Point）・26・34（見出し）・
40・44・50（大見出し）・70・80・100（KV/実績の数字）

- 書体は必ず `get_design_context` で取る（枠幅から字間を逆算しない）→ [DESIGN-SYSTEM-RULES.md](../general/DESIGN-SYSTEM-RULES.md)

## 5. 余白（スペーシング）

4pxグリッド。**gap / padding / margin に使う**。配置座標（`left`/`top` の Figma実測）は一点物なので**トークンにしない**。

`--space-4 / -5 / -6 / -8 / -10 / -12 / -16 / -20 / -24 / -32 / -40 / -44 / -56 / -60 / -72`（数字=px）

- グリッド外のカンプ固有値（`27` `34` `59` など）は Low/Mid では literal のまま。**High だけ**8pxグリッドへスナップ。

## 7. モーション

既存トークンを踏襲（`<style>` の2つ目の `:root`）＋今回1つ追加。

| トークン | 値 | 使いどころ |
|---|---|---|
| `--t-fast` / `--t-in` / `--t-big` | `.25s` / `.8s` / `1.3s` | 速さ：小さい反応 / 出現 / 大きい移動 |
| `--e-fast` | `cubic-bezier(.4,0,.2,1)` | ホバー等の標準 |
| `--e-out` | `cubic-bezier(.22,1,.36,1)` | 出現・移動の基本カーブ（直書き5箇所を集約） |
| `--e-soft` | `cubic-bezier(.22,.8,.28,1)` | 導入事例ホバーの“ふわっ”（直書き3箇所を集約・今回追加） |

## 8. 整理の記録（統合前 → 統合先 → 理由）

| 統合前 | → | 統合先 | 理由 |
|---|---|---|---|
| `#333`（1箇所） | → | `#333333`＝`--ink-label` | 色として完全に同一。表記ゆれを統一（見た目不変） |
| `rgba(255,255,255,.1)` と `.10` | → | `--glass-10` | 表記ゆれ。同一色（見た目不変） |
| `cubic-bezier(.22,1,.36,1)` 直書き | → | `--e-out` | 定義済みトークンと同値の二重管理を解消 |
| `cubic-bezier(.22,.8,.28,1)` 直書き×3 | → | `--e-soft`（新設） | 同カーブの二重管理を解消 |
| （Mid以上）`#9BE8A4` | → | `--code-green`(`#7CE7A6`) | 近すぎる緑2色を1つに |
| （Mid以上）`#434343` | → | `--surface-dark-bottom`(`#454545`) | 差2/256＝不可視 |
| （Highのみ）`#ACACAC` | → | `--line`(`#D1D5DC`) | 罫線グレーを1本化 |
| （Highのみ）`#333333` | → | `--ink`(`#101828`) | ラベル灰を本文色へ |
| （Highのみ）`#080A0E` | → | `--surface-cta`(`#090909`) | 端末の黒をCTA黒に統合（不可視） |
| （Highのみ）モック地 `#2B2B2B`/`#232323`/`#1B1B1B` | → | `--surface-dark-top`(`#161616`) | サーフェスを4色に集約（ガラス重ねで面は保つ） |

### ついでに気づいたこと（未変更・提案）
- `--surface-footer-bottom` と `--surface-dark-bottom` は現状ほぼ同値。Low では別トークンで温存、Mid/High で統合済み。
- コメント内に残る `#8a8f98` は旧グレーの言及のみ（実CSSでは未使用）。

## 9. 検証のしかた（実測。目視で「OK」と言わない）

ローカルで配信して、全要素の computed style を Low で撮り、整備前と**0差分**を確認した。

```bash
cd anyflow/v3 && python3 -m http.server 8799 &
# 整備前(復元ブランチ)と後で、色/背景/角丸/影/余白/font 等を全要素比較 → Low は 0 差分
```

- Low（`?ds=low`）= 現行と完全一致（実測0差分）。既定の High はそこから「1. 整備レベル」の表の分だけ違う。
- 既定=High / `?ds=low`=原状 / `?ds=high`=同じHigh、を実測確認済み（コード緑・ラベル色・罫線・サーフェス4色）。

## 11. これから値を足す時

1. `anyflow/v3/index.html` の `:root`（DS-TOKENS ブロック）に**名前を付けて**足す。
2. コンポーネントでは**その名前だけ**を使う（`var(--…)`）。
3. このドキュメントの表にも1行足す（早見表が古くなると意味がない）。
4. レベル差を付けたい値なら `html[data-ds="mid"]` / `["high"]` に上書きを足す。
5. 比較で確認 → `mock/design-system/`。

> KV・惑星・調整パネルは対象外。ここに px/HEX を足したくなっても、それは別世界の値。
